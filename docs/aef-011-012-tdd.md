## Real client evidence

`npx tsx scripts/verify-session-client.ts` passed on Windows/Node `24.16.0`, using authenticated Codex `0.162.0-alpha.17.2`. A freshly initialized isolated Git repository with a spaced path supplied fictional policy context. Two separate Codex invocations per session performed acknowledgement then read-only task execution. Both learning/no-learning outcomes were durably captured; replay left exactly one candidate, the source worktree stayed unchanged, and uninstall preserved an unrelated runtime setting. The [compact report](evaluations/aef-012-client-verification.json) retains versions, source/indexed revisions, generation, IDs, acknowledgement timestamps, outcomes and hashes without temporary paths or credentials.

The learning is an explicit synthetic protocol artifact, not an independently discovered fact. Acknowledgement establishes observed protocol consumption before task release; it cannot establish internal reasoning, universal policy compliance, native MCP template compatibility, write-enabled coding, global hook installation or SDLC Command wiring. Custom launchers remain explicitly unverified.

## Verification and limits

Passed: `npm run typecheck`, `npm run build`, `npm run validate:fixtures`, `npm run smoke:mcp` (real nine-tool SDK stdio), and `npm test` with scoped coverage (256/256 tests across 18 files). Aggregate feature coverage: statements 88.43% (627/709), branches 81.49% (414/508), functions 94.44% (68/72), lines 96.58% (453/469). All four 80% gates pass. This includes 33 safe-capture cases and 24 session cases. The unchanged retrieval evaluator also passes. Reproduce the aggregate feature coverage gate with:

```powershell
npm test -- --coverage --coverage.include=src/capture/candidate-store.ts --coverage.include=src/capture/review.ts --coverage.include=src/capture/safety.ts --coverage.include=src/capture/session.ts --coverage.include=src/capture/session-contracts.ts --coverage.reportsDirectory=.runtime/coverage-aef-011-012 --coverage.thresholds.statements=80 --coverage.thresholds.branches=80 --coverage.thresholds.functions=80 --coverage.thresholds.lines=80
```

The 80% threshold is aggregate across these feature modules, not every individual file or the entire repository. Real-client verification is explicit and separate from deterministic tests. Runtime databases, journal payloads, client schemas/output and coverage artifacts stay ignored. Full storage power-loss, network-filesystem and hostile-process races remain outside the demonstrated guarantees; see [behavior and recovery limits](safe-capture-and-sessions.md). Recovered publication still requires an explicit derived-index refresh. Legacy unversioned session receipts are rejected rather than silently upgraded to verified consumption. Actual receiving-system integration remains AEF-014.
