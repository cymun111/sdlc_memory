# Ranked and progressive retrieval

AEF-009 and AEF-010 extend the existing service and nine MCP tools. SDLC Command can request task summaries, retain their `index_generation`, and expand selected IDs with `expected_generation`. Actual receiving-system wiring and verified agent consumption remain AEF-014 and AEF-012 work.

## Deterministic ranking

`weighted-lexical-1` normalizes Unicode accents/case, removes a fixed stop-word list, applies a simple plural rule, and expands the explicit alternatives in [ranking.ts](../src/retrieval/ranking.ts). Examples include retry/replay/reattempt, idempotency/duplicate, reconciliation/compare, and image/picture. These are lexical heuristics, not general semantic understanding or extracted symbols.

Task text, each topic, and changed paths are independent positive signals. A text signal requires at least 60% of its normalized terms to match. A term contributes title 8, summary 5, body 1; topics multiply text weights by 1.5. Exact topic tags add 30 and explicitly declared source symbols add 40. Task tag/symbol matches add 24. Exact changed source paths add 60; directory prefixes add 20. Repository/cross-repository/team/shared scope adds 4/3/2/1. Verified or non-code evidence adds 3; other freshness states subtract 3. Equal scores sort by record ID. Returned reasons identify the matching fields and freshness state.

Authorization and editorial visibility precede matching; source/symbol fields use the authorized projection. Mandatory policies and conflict closure retain their separate handling. Parameterized FTS OR alternatives select at most 200 authorized narrative candidates in ID order. Authorized metadata is scored independently; candidates are bounded to the configured visit count (maximum 200) before freshness checks. Each field/query uses at most 32 normalized terms; body inspection is additionally bounded to 16,384 characters, topics to 32, paths to 100, and lexical alternatives to 64. Long narratives can therefore miss matches; there is no unbounded corpus or latency claim. Paths use repository-relative, case-sensitive source declarations. The synonym list can produce extra matches; evaluate representative tasks before expanding it.

## Expansion and budgets

MCP `search_knowledge`, `get_knowledge`, and `get_related` accept optional `expected_generation`, `cursor`, `max_bytes`, and `max_tokens`. `get_task_context` and the versioned facade accept generation and byte controls alongside their existing token budget. Existing CLI query/get calls retain their defaults; use MCP or the service API for continuation controls.

Start a read without a cursor, then repeat the same request with its `next_cursor` until null. Preserve `expected_generation` from the summary. Reads reject a changed active generation with `CONFLICT`; they do not load historical index generations. Cursors bind the normalized request, canonical repository, principal/configuration, generation/provenance, visible conflicts, and operation data. A changed snapshot, configuration, checkout drift, or incompatible request requires restarting without a cursor (`VALIDATION_ERROR`). Cursors are opaque continuation values, not authentication credentials.

Body pages include `body_offset` in UTF-8 bytes and cut only at code point boundaries. Concatenate `body` in page order. `byte_limit` continues to cap body bytes; the smaller configured/requested `max_bytes` separately caps the complete logical response. Related pagination emits node events followed by unique edge events; an edge can reference authorized nodes from earlier pages, and a page can contain only edges. Follow every page to reconstruct the bounded graph. `omitted_result_count` and `omitted_edge_count` count remaining events; `visited_nodes`, configured depth and visit limits still bound traversal. Traversal truncation can remain true after pagination ends.

Budgets measure serialized UTF-8 `{ok:true,data:...}`, including evidence, provenance, conflicts, cursor, estimator fields, and facade/delivery wrappers. Discovery and map responses also enforce configured token and byte caps. The conservative labeled estimate is `ceil(bytes/3)`, not a model tokenizer. JSON-RPC framing and MCP's duplicate text representation are excluded. Facade wrappers reserve space and undergo a final envelope check; the nested context estimate describes its own envelope.

If metadata or the next indivisible summary/edge cannot fit, retrieval returns `CONTEXT_BUDGET_EXCEEDED`, rather than an empty page with a non-advancing cursor. Large evidence can require a larger budget or narrower request. Required policy omission remains an explicit blocking context status with omitted IDs, or a domain error if even that blocking envelope cannot fit. Minimal structured error envelopes are an exception to caller budgets, including budgets smaller than the error itself. No successful over-budget envelope is returned. Private prose classification, shared authentication, caching, retained-generation reads and automatic agent planning remain outside these features.
